# Flightwatch: авиабилеты в Telegram

Python-сервис для мониторинга цен Aviasales, истории минимумов и обновления подборки в Telegram. Использует бесплатный Data API Travelpayouts и SQLite, не требует сторонних Python-пакетов.

> Источник возвращает кэш поисков пользователей, а не живые предложения продавцов. Цены, наличие мест и условия тарифа нужно проверять перед покупкой.

## Возможности

- Несколько городов вылета, дополнительные запросы SVO, DME и VKO для Москвы.
- Фильтры дат, основной цены и количества пересадок. Исключение пересадок в России.
- Удаление дублей с сохранением минимальной цены.
- Одна компактная подборка, сгруппированная по городам: прямые рейсы ✈️, затем варианты с пересадкой 🔁, внутри групп — по цене.
- Местное время вылета, город пересадки и её длительность, если данные позволяют.
- Почасовое редактирование последнего сообщения вместо новых сообщений.
- Кнопка **«Обновить цены»** для проверки рейсов из конкретной подборки.
- Команда `/search` для новой подборки; в группе можно использовать `/search@имя_бота`.
- Отметки изменений: `🆕 🟢 (старая цена)` при снижении, `🆕 🔴 (старая цена)` при повышении.
- Минимум наблюдавшихся цен за 7 суток для каждого рейса. Знак ✓ означает совпадение с текущей ценой.
- Ночной режим по Europe/Samara: с 00:00 до 09:00 автоматическое обновление только для дешёвых билетов.

Ручные команды и кнопка действуют и ночью. Команды принимаются только из настроенного чата.

## Пример

**Москва**

✈️ **39 280 ₽** · 24.11 22:25 · SVO → CXR · мин. 7д: 39 280 ₽ ✓

🔁 **30 139 ₽** · 24.11 23:15 · SVO → Гуанчжоу (CAN, 3 ч) → CXR 🆕 🟢 (32 500 ₽)

Обновлено: 26.10.2026 12:00:00 (Самара)

Пример иллюстративный. В Telegram цена подчёркнута и является ссылкой на предложение.

## Быстрый старт

Требуется Python 3.11+ на Linux или macOS. Для проверки без ключей и сетевых запросов:

```sh
python3 flightwatch.py --demo
python3 -m unittest discover -s tests -v
```

Для настоящего поиска:

1. Зарегистрируйтесь в [Travelpayouts](https://www.travelpayouts.com/) и получите токен **Data API** в профиле. Соблюдайте условия программы Aviasales.
2. Создайте бота через [BotFather](https://t.me/BotFather), добавьте его в нужный чат и отправьте `/start`.
3. Создайте локальный `.env` по образцу `.env.example`:

```dotenv
TRAVELPAYOUTS_TOKEN=
TELEGRAM_BOT_TOKEN=
TELEGRAM_CHAT_ID=
```

ID чата находится в `message.chat.id` ответа Telegram `getUpdates`. Для групп он обычно отрицательный. `.env`, базы данных и логи исключены из Git.

```sh
chmod 600 .env
python3 flightwatch.py                         # поиск без отправки
python3 flightwatch.py --send                  # новая подборка
python3 flightwatch.py --send --update-latest  # обновить последнюю
python3 flightwatch.py --watch --send --update-latest
```

Для обработки команд и кнопок запустите отдельный процесс:

```sh
python3 bot.py
```

Обработчик использует long polling. Запускайте только один `bot.py` с одним токеном. Открывать входящие порты не требуется.

## Настройки

`config.json` содержит пример поездки в Нячанг на ноябрь 2026 года. Перед использованием обновите даты и маршруты.

| Поле | Значение |
| --- | --- |
| `origins` | IATA-коды городов или аэропортов вылета |
| `moscow_airports` | Дополнительные аэропорты при наличии MOW в `origins` |
| `destination` | Город или аэропорт прибытия |
| `departure_start`, `departure_end` | Включительные границы дат вылета |
| `max_price` | Основная цена на человека, включительно; `null` — без потолка |
| `max_transfers` | Максимум пересадок; текущий формат рассчитан на 0–1 |
| `exclude_russian_connections` | Исключать российские и нераспознанные пересадки |
| `currency` | RUB; ночной порог и подписи минимумов рассчитаны на рубли |
| `interval_seconds` | Интервал запуска с `--watch` |
| `quiet_start_hour`, `quiet_end_hour` | Ночной интервал по Europe/Samara |
| `night_price_threshold_rub` | Строгий верхний порог ночных обновлений |

В примере: Ижевск, Екатеринбург, Казань, Пермь, Москва, Уфа → Камрань (CXR), 10–30 ноября, до 55 000 ₽. Ночью — строго дешевле 37 000 ₽. Багаж не оценивается: основная цена API может включать его или не включать. Поле `top_n` сохранено для совместимости; количество строк ограничивается длиной сообщения, а не этим полем.

Если список не помещается в лимит Telegram, в конце указывается число непоместившихся вариантов. Время внизу сообщения означает время проверки, а не обновления кэша Aviasales.

## Сервер с systemd

Разместите проект на Linux-сервере в `/opt/flightwatch`, включая локальный `.env`. Затем:

```sh
sudo useradd --system --home-dir /opt/flightwatch --shell /usr/sbin/nologin flightwatch
sudo mkdir -p /opt/flightwatch/data
sudo chown -R flightwatch:flightwatch /opt/flightwatch
sudo chmod 600 /opt/flightwatch/.env
sudo cp deploy/flightwatch.service deploy/flightwatch.timer deploy/flightwatch-bot.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now flightwatch.timer flightwatch-bot.service
```

Таймер выполняет проверку каждый час с задержкой до 30 секунд, возобновляет работу после перезагрузки и выполняет пропущенную проверку после простоя. Интервал systemd задаётся в `deploy/flightwatch.timer`, отдельно от `interval_seconds`.

```sh
systemctl list-timers flightwatch.timer
journalctl -u flightwatch.service -n 50 --no-pager
journalctl -u flightwatch-bot.service -n 50 --no-pager
sudo systemctl start flightwatch.service
sudo systemctl disable --now flightwatch.timer flightwatch-bot.service
```

## Docker

Альтернативный запуск мониторинга:

```sh
docker compose up -d --build
docker compose logs --tail=50 -f
```

История сохраняется в именованном volume. `docker compose down` сохраняет её; не используйте `-v`, если хотите сохранить базы. После изменения настроек перезапустите контейнер. Текущий Compose запускает только мониторинг, без `bot.py`; для команд и кнопок используйте systemd. Не включайте два планировщика одновременно.

## История

В каталоге `data/` автоматически создаются:

- `prices.sqlite3` — цены, валюта, идентификатор рейса и время наблюдения.
- `messages.sqlite3` — снимки подборок для сравнения и редактирования сообщений.
- `bot.sqlite3` — позиция чтения команд Telegram.
- `search.lock` — блокировка одновременных поисков.

Минимум за 7 суток строится по наблюдениям сервиса, показывается после двух записей и не является рыночным минимумом. При повторной проверке без изменения цены отметки 🆕🟢🔴 исчезают. `/search` создаёт новое сообщение, после чего планировщик обновляет его. Старые подборки можно обновлять их собственными кнопками.

## Ограничения

- API возвращает не все существующие рейсы и тарифы. Отсутствие результата не доказывает отсутствие билетов.
- Кнопка повторно запрашивает кэш. Отсутствующее предложение помечается как неподтверждённое.
- Изменение времени сопоставляется по дате, авиакомпании, номеру рейса, аэропортам и пересадке. Перенос на другую дату и фактический статус рейса не отслеживаются.
- Аэропорт пересадки извлекается из недокументированного параметра ссылки `t`. При несовпадении формата вариант исключается. Изменение ссылок может сократить выборку.
- Ожидание при одной пересадке рассчитывается по разнице `duration` и `duration_to`. Это проверено на отдельных примерах интерфейса Aviasales, но не является гарантированным контрактом API. При недостаточных данных выводится «время уточняется».
- Поддерживается один взрослый, эконом, в одну сторону.
- Справочники в `resources/` получены из публичных данных [аэропортов](https://api.travelpayouts.com/data/en/airports.json) и [городов](https://api.travelpayouts.com/data/ru/cities.json) Aviasales. Их актуальность зависит от даты загрузки.
